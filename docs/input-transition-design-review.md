# USB input transition design review

Implementation follow-up: this is the initial design audit. The implemented mode requires an application guest-consumption adapter and is off by default in the generic toolkit; there is no implicit USB-only retirement fallback. The game opts in and defers gameplay-button acknowledgement through the human fighter read. Independent queue, SDL host and actual OHCI walker fixtures now verify ordering, bounds, cancellation, snapshots, failed/empty/partial TD retention, full successful delivery and unchanged-report NAK. A later partial-transfer issue found by the new walker fixture was fixed by requiring the full report bytes to move before delivery is committed. See the game repository's `docs/research/input-transition-fix-2026-10-30.md` for measured behavior and validation.

## Current path and failure mode

`usb_gamepad_report` (usb_gamepad.c:806-818) takes `s_sample_cs`, reads a fresh host/script state, merges the sampler latch, clears that latch, applies a wall-clock `min_hold`, and returns a level snapshot. A sampler thread starts on first report and samples all four pads every 4 ms (718-752). It latches only `out[2]` and analog bytes 4..11 (731-734); it does not latch digital byte 3. Thus quick down/up between USB queries becomes one pressed level, but repeated transitions of the same bit before a report collapse into one OR bit. The hold timer begins when report construction sees a pressed value, not when a guest consumes it; default is 120 ms (766-804). It can keep an already-consumed press down and cannot guarantee delivery of a distinct press after a release if reports are merged.

The OHCI worker calls `usb_gamepad_report` while walking a periodic IN TD (ohci.c:925-975), then compares against the last successfully sent report. An unchanged report NAKs by leaving the TD queued (943-945). A changed report calls `ohci_do_td`; the prior latch has already been cleared even if the TD fails (970-985). Only `TD_CC_NOERROR` updates `s_last_report` / `s_report_sent` (971-975). Failures include bad guest buffer (return 12 at 745), stall, and short-IN data underrun where buffer rounding is absent (834-835). Therefore report generation is currently treated like consumption for latch clearing, but is neither successful transfer nor guest consumption.

The OHCI bus worker is serialized with MMIO acknowledgement using `s_bus_cs` (ohci.c:204-216); it holds that lock through list walking and only releases it before interrupt delivery (1276 onward, `deliver`). `usb_gamepad_report` is called on that worker and nests its sample/latch locks. Sampler and report both acquire `s_sample_cs` before any latch operation; sampler releases sample lock before acquiring latch lock, so there is no current inverse nested order. Avoid an acknowledgement callback that takes the bus lock while called under a pad lock or while MMIO acknowledgment already holds it. Prefer a short per-pad queue lock with a documented order, or have the guest-ack hook publish an atomic token that the input owner consumes.

OHCI `s_report_sent` is only a device-side cache. The guest clears `INTR_WDH`/done state after the OHCI worker publishes a done queue; that acknowledges descriptor processing, not necessarily the game's later use of the copied pad state. A successful TD is likewise not proof that the game's update consumed the input. A game-specific optional consumption hook is the only reliable semantic acknowledgement; keep an explicit fallback (successful USB/WDH completion) for titles without one and label it weaker.

## Minimal bounded design

Keep continuous axis/current state separate from button transitions. The sampler should compare each new host/script sample with a per-pad prior sample and enqueue button state transitions independently of report cadence. Define the complete 16-bit digital field from report bytes 2-3; the current latch only handles the low eight bits. Analog buttons/triggers in bytes 4-11 can use the same transition mechanism (press threshold and release threshold must be explicit); axes remain latest-value snapshots to avoid queueing noisy motion.

Represent each pending item as a monotonically increasing per-pad sequence plus a button-state snapshot (digital 16-bit mask and analog button values), or an equivalent transition record that cannot combine a down and a later up into one OR. `usb_gamepad_report` should peek the oldest item and produce that state, without removing it. The OHCI path should retain a report token through transfer processing and commit only after `ohci_do_td` succeeds; NAK, stall, invalid buffer, underrun, and unexecuted TD leave the token pending. Where a guest/title hook exists, retire that token only on explicit guest-consumption acknowledgement. Class GET_REPORT must follow a documented policy too: either expose/ack the same token after a complete successful control data stage or keep it snapshot-only; it must not silently consume an interrupt token during report construction.

Bound storage per pad (small fixed ring) and make overflow visible. Never grow a queue for a title that has stopped consuming input. On overflow, use a deterministic bounded policy (for example discard the oldest stale item while retaining the newest state, increment a counter, and emit a trace reason); do not block the sampler or USB worker. Add an age limit for unacknowledged commands, then collapse to the latest physical state and report a timeout/drop. Focus loss and UI deactivation must clear pending transitions and reset the baseline to released; host input already reads pads as resting when unfocused and releases keyboard state (`input_host.c:498-520,1001-1005`). Device removal/disconnect should similarly clear that pad's queue and establish a neutral baseline. Reconnect must not replay pre-unplug taps. Scripted input is also sampled by `sample_now`; retain current script timing and host-suppression (`usb_gamepad.c:821-850,917+`) and route script transitions through the same bounded queue only if tests confirm deterministic timing. Preserve an opt-out compatibility mode for legacy level/min-hold behavior during rollout.

Do not hold a transition solely for a fixed 1 ms or 120 ms timer when a consumer acknowledgement is available. If no optional title hook is installed, use transfer/WDH acknowledgement as a compatibility fallback, with a configurable maximum age and an observable pending/drop counter. A report can contain a combined snapshot for different buttons whose edges occur close together, but an individual button's press and release must never be folded into the same queued state or lost by a level OR.

## Existing coverage and missing fixtures

`tests/usb_transfer/test_main.c` includes the private OHCI walker, verifies four-pad routing, indexed scripts/reset, descriptors and the shared done queue, and explicitly sets `RECOMP_PAD_MIN_HOLD_MS=0` (lines 33-71). It does not assert rapid transitions, sampler concurrency, report retry, focus/unplug clearing, full 16-bit edge preservation, or acknowledgement behavior. `tests/usb_ohci_posix` checks MMIO trap routing only and skips on unsupported hosts. `tests/input_host` exercises host mapping/device behavior but not USB transition serialization. No existing test names or assertions cover min-hold/latch transitions.

Suggested bounded fixtures (extract queue logic behind a pure state API so these need no host sampler or game):

1. For each digital bit in bytes 2-3, enqueue down then up before a report; assert two distinct snapshots in order, then empty after acknowledgements. Repeat for all eight analog button channels at chosen thresholds.
2. Enqueue down/up/down before reads; assert all three snapshots survive in order. Verify a held button produces no duplicate edge and a same-state sample does not grow the queue.
3. Peek without ack, report the same token again, and assert it remains pending. Ack that token, then assert the next transition is next; reject stale/out-of-order tokens.
4. Through OHCI, test successful TD retires only at the documented ack point; NAK and invalid-buffer / stall / DATAUNDERRUN retain the event. Ensure failed TD does not update last-successful-report state.
5. Fill ring to capacity and exceed it; assert fixed memory, deterministic overflow policy/counter, and no block. Test max-age expiry.
6. Focus loss, UI deactivation, unplug, and USB reset clear pending transitions without cross-pad effects; reconnect while held establishes a fresh baseline rather than replaying stale press.
7. Scripted and legacy nonhost inputs retain specified scheduling/hold behavior; `RECOMP_PAD_MIN_HOLD_MS=0` remains a compatibility path if kept.

The OHCI-specific tests must distinguish a transfer's `TD_CC_NOERROR`, HCCA done-queue publication, WDH acknowledgement, and actual title consumption. Those are different milestones; asserting only `usb_gamepad_report` output would miss the current drop-on-failed-TD path.
